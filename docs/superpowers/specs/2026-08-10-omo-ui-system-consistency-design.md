# Omo 全局 UI 语义一致性设计

## 背景

Omo 的首页、知识库和主动回忆流程已经形成经过 Figma 与 Simulator 验证的视觉母语：珊瑚色环境、奶油色内容表面、青绿色操作色，以及通过圆润形状、低频动效和 Omo 角色建立的温暖感。

后续加入的“我的”、设置、隐私、上传和两类详情页分别沿用了黄绿色主题或 iOS 系统默认样式。代码中同时存在 `RecallPalette` 与 `OmoTheme` 两套颜色体系，导航、关闭、主要操作、重试和危险操作也缺少统一的位置与组件合同。这使页面虽然分别可用，却不像同一个产品。

本设计以用户确认的方案 A 为准：以首页既有的珊瑚、奶油、青绿视觉语言作为全 App 唯一母语，统一全部页面与控件语义，同时保留已经确认的核心交互和业务合同。

## 目标

1. 同一语义的颜色、文字、按钮、导航和状态反馈在全部页面保持一致。
2. 同一层级的页面使用稳定的位置模型，用户能凭位置理解返回、关闭、创建和主要操作。
3. SwiftUI 代码通过语义 token、共享组件和 Scaffold 防止后续继续漂移。
4. 保留首页、抽卡、刮刮乐、自评、截图任务恢复、知识库搜索和后端合同的现有行为。
5. 通过代码检查、Simulator 用户路径、截图比较和自动测试共同验收，而不是只检查编译。

## 非目标

- 不重新设计 Omo IP、动画资产、抽卡机制、刮刮乐或自评算法。
- 不改变截图上传、AI 许可、任务恢复、搜索、通知、assessment 或 API 合同。
- 不引入深色主题，也不为单个机型建立布局分支。
- 不把稀有度变成交互、概率、掌握度或付费语义。
- 不部署 Railway production，不修改 `main`，不替换旧 Recallo App。

## 审查证据

### 运行与截图证据

- 新鲜 Debug 构建已在 `Omo Verify iPhone 17 Pro` Simulator 成功编译并启动，首页显示珊瑚环境、奶油面板和青绿上传按钮。
- 仓库中的 Release/Simulator 基线截图覆盖首页空态、处理中、失败、回忆刮开、自评、知识库、上传、完整上下文、完整知识和“我的”。
- 对比结果显示：核心流程使用珊瑚体系；“我的”和完整知识使用黄绿色体系；Settings 使用系统灰白 List；上传 Sheet 同时继承黄绿背景和系统导航。

### 代码证据

- `RecallDesign.swift` 定义 `RecallPalette`，服务首页、知识库、回忆卡和自评。
- `ContentView.swift` 另行定义 `OmoTheme`，服务 Profile、上传、完整知识和启动页。
- Settings、隐私和部分 Toolbar 依赖系统默认颜色、List 表面与按钮样式。
- Library/Profile 的返回动作、Sheet 的关闭/完成、上传 CTA、重试动作和卡片链接没有共享位置或组件合同。
- 页面中存在散落的裸字号、圆角、阴影、系统紫色/橙色和局部透明度计算。

## 视觉基础

### 颜色语义

全 App 只保留一套公开的语义颜色。旧名称可以在迁移期作为私有兼容别名，但页面代码不得继续直接选择两套主题。

| Token | 语义 | 默认来源 |
|---|---|---|
| `canvas` | 一级页面环境背景 | 现有 `RecallPalette.background` 珊瑚色 |
| `surface` | 主面板、卡片、阅读表面 | 现有奶油面板色 |
| `surfaceElevated` | 顶部按钮、浮层、较高层级卡片 | 比 `surface` 更浅的奶油色 |
| `primary` | 主要操作、导航图标、交互描边 | 现有青绿色 |
| `primarySoft` | 选中背景、装饰填充、弱状态 | 现有柔和青绿 |
| `accent` | 已揭示语义、当前页、关键强调 | 现有珊瑚强调色 |
| `textPrimary` | 标题、正文、重要数字 | 现有深青墨色 |
| `textSecondary` | 解释、元数据、辅助说明 | 从 `textPrimary` 派生的固定弱对比色 |
| `error` | 失败与危险操作 | 现有错误红色 |
| `scrim` | 抽屉与模态遮罩 | 固定黑色透明度 |

`R / SR / SSR` 可保留独立装饰色，但必须进入 `OmoRarityColor`，不得在页面内直接写 `.purple`、`.orange` 或任意色值。

### 文字语义

使用 Dynamic Type 语义样式建立统一层级：

- `pageTitle`：一级内容页面标题。
- `sectionTitle`：区段标题。
- `cardKnowledge`：知识卡正文。
- `body`：解释与长文本。
- `metadata`：来源、状态、统计标签。
- `action`：按钮文字。
- `status`：处理中、失败和重试提示。

允许知识卡正文根据已确认设计使用 rounded 字体；系统说明、隐私和设置正文优先使用系统 text style。页面不得新增裸字号，确需保留的 Figma 参考尺寸必须集中到组件 Metrics，并通过 `@ScaledMetric` 响应 Dynamic Type。

### 空间、圆角与阴影

- 页面水平安全内边距统一为语义 token。
- 控件最小触控尺寸为 44pt。
- 主按钮高度、图标导航外壳、卡片圆角、Sheet 圆角和阴影分别只有一个共享来源。
- 阴影只表达层级，不用不同颜色和强度装饰同族按钮。
- 首页和知识库已有 402 × 874 参考画布继续使用集中 Metrics；其他页面使用 safe area、自适应布局和共享 Scaffold。

## 导航与动作语义

### 一级页面

- 首页左上角显示菜单按钮。
- 知识库和“我的”作为从首页进入的一级子页面，在相同的左上参考位置显示返回按钮。
- 菜单与返回共用 `OmoTopIconButton` 的尺寸、奶油表面、青绿图标、圆角、阴影和触控区，只替换图标与 accessibility 文案。

### 模态页面

- 上传、设置、隐私、完整知识和完整上下文属于模态/阅读层。
- 它们使用右上角统一的 `OmoSheetDismissButton`；根据语义显示“关闭”或“完成”，但位置、字体、颜色、表面和命中区域相同。
- “返回”不用于关闭 Sheet，“完成”不用于一级页面回到首页。

### 创建动作

- 右下加号只存在于首页和知识库，语义固定为“上传新的知识截屏”。
- 两处共用同一 `OmoCreateButton`，位置由各自 Scaffold 的 bottom-trailing anchor 决定，不能在页面中重新声明视觉样式。
- 处理截图时创建按钮仍可使用；正在提交当前选择时，仅上传 Sheet 内的主要按钮进入 loading/disabled 状态。

### 操作层级

| 角色 | 视觉 | 示例 |
|---|---|---|
| Primary | 青绿填充、奶油文字、统一高度和圆角 | 选择截图、继续上传截图 |
| Secondary | 奶油高层表面、青绿文字与描边 | 非主要补充动作 |
| Tertiary | 透明表面、青绿文字或图标 | 查看原文、轻量导航 |
| Status action | 位于状态内容附近的紧凑操作组件 | 搜索重试、截图任务重试 |
| Destructive | 错误色文字/描边，不使用 Primary 填充 | 撤回 AI 处理许可 |

禁用状态使用共享 token，必须同时改变颜色、阴影和 accessibility enabled 状态；不能只降低文字透明度。

## 页面设计

### 首页与主动回忆

- 保留现有 Figma 构图、IP、收藏夹、上传、卡堆、刮层和自评条。
- 将现有颜色、圆角、阴影和字号映射到正式语义 token，不改变位置与手势。
- 菜单、收藏夹和上传在空闲、抽取、刮开、自评和换卡状态持续可见。
- 失败与处理中信息使用共享 status typography；重试使用 `OmoStatusAction`。

### 知识库

- 保留现有有机面板、搜索栏、两列分页、完整卡片和底部收藏夹/上传构图。
- 返回按钮迁移到 `OmoTopIconButton`。
- 搜索提交、空态 CTA、失败重试与截图任务重试使用统一动作角色。
- 搜索框内部的语音、提交、loading 和 disabled 状态继续保持原行为，但颜色与文字来源统一。

### 我的

- 保留标题、Omo 身份区、记忆足迹和今日召回状态的信息结构与响应式布局。
- 页面环境改为珊瑚；身份舞台、统计卡和状态面板改为奶油表面与青绿/珊瑚强调。
- 返回按钮改为与知识库相同的左上导航组件。
- 删除黄绿色专属视觉 token，不增加账号、头像或通知等未实现能力。

### 设置与隐私

- 标题统一为中文“设置”。
- 不再使用系统灰白 grouped List 作为最终视觉；改为奶油阅读 Sheet 中的统一区段与行组件。
- 复习说明是只读信息，隐私说明和联系支持是导航/链接，撤回 AI 许可是 destructive action。
- 隐私页复用同一 Sheet Scaffold、标题、区段和正文体系。

### 上传

- 使用奶油模态表面、统一右上关闭和 Primary 选择按钮。
- 保留 IP 动画、AI 许可弹窗、PhotosPicker、提交进度和错误逻辑。
- 标题、说明、loading 与 disabled 颜色统一，不使用黄绿背景。

### 完整知识与完整上下文

- 两者共享 `OmoReadingSheetScaffold`、右上完成按钮、内容宽度、分隔线、来源状态和外链样式。
- 完整知识可以展示稀有度和掌握信息；完整上下文继续展示知识、解释与来源完备度。
- 揭示前的完整上下文入口仍遵守现有 reveal 合同，不因视觉重构泄露承重语义。

## 组件与文件边界

### 设计系统

在 `Omo/Omo/DesignSystem/` 建立聚焦文件：

- `OmoDesignTokens.swift`：颜色、文字、间距、圆角、阴影、状态与稀有度 token。
- `OmoButtons.swift`：顶部图标、Sheet 退出、创建、Primary、Secondary、Status、Destructive 组件/样式。
- `OmoScaffolds.swift`：自适应页面、模态阅读页和区段表面。

`RecallDesign.swift` 只保留首页、卡堆、自评与知识库的组件/屏幕 Metrics；通用颜色迁出。

### 页面

- `RecallHomeView.swift`、`KnowledgeLibraryView.swift`、`ProfileView.swift` 使用共享顶部与动作组件。
- `ContentView.swift` 不再定义第二套 Theme；上传、设置、隐私和完整知识可按职责拆成独立 View 文件，避免继续扩大路由文件。
- `RecallKnowledgeCardView.swift` 的上下文 Sheet 使用共享阅读 Scaffold。

## 状态与错误处理

- loading、disabled、empty、failed、retrying 和 success 均有明确且一致的视觉状态。
- 页面路由、截图任务和卡片状态仍由现有 `OmoStore` 与 ViewModel 驱动；视觉组件不持有业务事实。
- 状态操作必须保留原页面入口，不能因 loading 或错误遮挡菜单、返回、知识库、上传或可用的抽卡入口。
- Sheet 关闭后返回触发它的页面与状态，不重置当前回忆轮次或任务。

## 可访问性与动效

- 图标按钮必须有明确 label/hint；同语义按钮在不同页面使用同一 accessibility 角色。
- 所有操作至少 44pt，文字支持 Dynamic Type，长正文可滚动且不横向溢出。
- Reduce Motion 保留完整结果与状态，只减少过场、弹簧和呼吸动画。
- 揭示前不在 VoiceOver label/value/hint 中暴露 `hiddenSemantic`。
- 颜色不是唯一状态线索：错误、loading、selected 和 disabled 同时通过文案、图标、描边或进度反馈表达。

## 验收矩阵

### 页面与状态

必须实际打开并检查：

1. 首页空库、处理中、失败、有卡空闲。
2. 抽卡过场、未刮、部分刮开、80% 揭示、自评取消、自评提交、提交失败重试、完成回首页。
3. 知识库空态、有卡、处理中、失败、文字搜索、语音状态、无结果、搜索失败、分页与卡片详情。
4. 我的普通数据、大数字、无到期卡、有到期卡。
5. 设置、隐私、上传空闲、上传中、AI 许可。
6. 完整知识与完整上下文。

### 设备与辅助功能

- 常见 iPhone Simulator。
- 更小的 iPhone Simulator。
- 默认字号与至少一个 Accessibility 字号。
- Reduce Motion。
- VoiceOver 语义树与关键路径。
- 键盘、焦点、安全区、滚动和横向溢出。

### 代码与自动化

- 设计 token 和共享控件单元/快照可验证部分优先测试先行。
- 扩展 UI Test，断言同语义导航、关闭、创建和主要操作在各页面可达并能返回。
- 运行全部 iOS XCTest/UI Test、文档检查和 `git diff --check`。
- 保存改动后的关键状态截图，与本设计中的改动前证据逐页比较。

## 成功标准

1. 页面代码不再直接依赖两套 Theme；通用颜色只有一个语义来源。
2. 一级返回、模态退出、创建、Primary、Status 和 Destructive 操作各自只有一个共享实现或明确变体。
3. 首页、知识库、“我的”、设置、隐私、上传和详情在视觉上属于同一产品。
4. 原有核心交互和恢复路径全部通过回归测试，用户不会因视觉重构进入死路。
5. Simulator 逐页检查、辅助功能检查、自动测试和截图证据共同支持完成结论。
